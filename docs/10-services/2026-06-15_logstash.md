# Logstash Service

**Service Name:** `smart-noc-logstash`  
**Image:** `docker.elastic.co/logstash/logstash:8.12.0`  
**Status:** Core Service  
**Uptime Target:** 99.9%

---

## Overview

Logstash is the **entry point** for all network device logs in the Smart NOC system. It receives syslog messages via UDP/TCP, parses them using grok patterns, enriches them with device metadata, and publishes structured events to Kafka for downstream processing.

---

## Service Configuration

### Ports
- **5000/tcp:** Syslog input (TCP)
- **5000/udp:** Syslog input (UDP)
- **9600/tcp:** Monitoring API

### Resources

```
LS_JAVA_OPTS: "-Xmx2048m -Xms1024m"
log.level: error
xpack.monitoring.enabled: false
```

## Architecture Components

### 1. **Input Stage**
**Purpose:** Receive syslog messages from network devices

**Supported Protocols:**
- UDP 5000 (default for most network devices)
- TCP 5000 (reliable delivery, used for critical devices)

**Syslog Formats Supported:**
- RFC3164 (BSD syslog): `<pri>timestamp hostname message`
- RFC5424 (IETF syslog): `<pri>version timestamp hostname app-name ...`
- Extreme Networks format: Custom vendor-specific patterns

**Example Input:**
```
<189>Jun 13 22:51:55 10.139.38.188 Port 1:55 link DOWN
```

---

### 2. **Filter Stage**

#### **Phase 1: Grok Parsing**

**Pattern Matching:**
1. **Extreme Networks Pattern:**
   ```
   <%{POSINT:syslog_pri}>%{SYSLOGTIMESTAMP:syslog_timestamp} %{IPORHOST:syslog_hostname} %{GREEDYDATA:syslog_message}
   ```

2. **RFC5424 Pattern:**
   ```
   <%{POSINT:syslog_pri}>%{NONNEGINT:syslog_version} %{TIMESTAMP_ISO8601:syslog_timestamp}...
   ```

3. **Generic RFC3164 Pattern:**
   ```
   <%{POSINT:syslog_pri}>%{SYSLOGTIMESTAMP:syslog_timestamp} %{SYSLOGHOSTNAME:syslog_hostname}...
   ```

**Extracted Fields:**
- `syslog_pri`: Priority (facility × 8 + severity)
- `syslog_timestamp`: Device timestamp
- `syslog_hostname`: Device identifier (IP or hostname)
- `syslog_message`: Raw message content

#### **Phase 2: Device ID Assignment**

**Logic:**
```
IF syslog_hostname exists:
    device_id = syslog_hostname
ELSE IF metadata.host exists:
    device_id = metadata.host
ELSE:
    device_id = "unknown"
```

**Purpose:** Ensure consistent device identifier for enrichment lookup

#### **Phase 3: Event Type Detection**

**Pattern Matching (Case-Insensitive):**

| Event Type | Regex Pattern | Examples |
|------------|---------------|----------|
| `INTERFACE_UP` | `/(link\|interface).*(up\|active\|enabled)/i` | "Port 1:55 link UP", "Interface active" |
| `INTERFACE_DOWN` | `/(link\|interface).*(down\|inactive\|disabled)/i` | "Port 2:22 link DOWN" |
| `BGP_SESSION` | `/bgp.*(up\|down\|established\|reset)/i` | "BGP peer 10.0.0.1 established" |
| `OSPF_NEIGHBOR` | `/ospf.*(up\|down\|adjacency)/i` | "OSPF neighbor 192.168.1.1 down" |
| `AUTH_FAILURE` | `/auth(entication)?.*(fail\|denied)/i` | "Authentication failed for user admin" |
| `unknown` | Default | All unmatched messages |

#### **Phase 4: Interface Extraction**

**Extreme Networks (EXOS/VOSS):**
- **Pattern:** `[Pp]ort\s+(?<interface>\d+:\d+)`
- **Examples:** "Port 1:55", "port 7:77"
- **Format:** `X:Y` where X=slot, Y=port

**Cisco IOS:**
- **Pattern:** `(?<interface>GigabitEthernet\d+/\d+/\d+)`
- **Examples:** "GigabitEthernet1/0/1"

**Juniper JunOS:**
- **Pattern:** `(?<interface>ge-\d+/\d+/\d+)`
- **Examples:** "ge-0/0/0"

#### **Phase 5: Device Enrichment**

**HTTP Enrichment Service Call:**

**Endpoint:** `http://device-enrichment:8080/device/{device_id}`

**Request:**
```http
GET /device/10.139.38.188 HTTP/1.1
Host: device-enrichment:8080
```

**Response (cached):**
```json
{
  "device_id": "10.139.38.188",
  "vendor": "Extreme Networks",
  "device_family": "EXOS",
  "model": "X690-48x (2-slot stack)",
  "os_version": "32.6.1.2",
  "cli_syntax": "EXOS",
  "device_role": "core"
}
```

**Enriched Fields Added:**
- `device_vendor`: "Extreme Networks"
- `device_family`: "EXOS"
- `device_model`: "X690-48x (2-slot stack)"
- `device_os_version`: "32.6.1.2"
- `device_cli_syntax`: "EXOS"
- `device_role`: "core"

**Fallback Behavior:**
- If enrichment fails → fields remain null
- If device not found → fields remain null
- Logs continue processing (non-blocking)

#### **Phase 6: Metadata Addition**

**Added Fields:**
- `@timestamp`: Logstash processing timestamp (ISO8601)
- `log_source`: "syslog"
- `pipeline_version`: "2.0"
- `enrichment_status`: "success" | "failed" | "not_found"

---

### 3. **Output Stage**

#### **Primary Output: Kafka**

**Topic:** `network-logs`

**Kafka Configuration:**
```
bootstrap_servers: ["kafka:9092"]
topic: "network-logs"
codec: json
acks: 1
compression_type: "snappy"
```

**Message Format:**
```json
{
  "@timestamp": "2026-06-13T22:51:55.123Z",
  "device_id": "10.139.38.188",
  "syslog_hostname": "10.139.38.188",
  "syslog_message": "Port 1:55 link DOWN",
  "event_type": "INTERFACE_DOWN",
  "interface": "1:55",
  "device_vendor": "Extreme Networks",
  "device_family": "EXOS",
  "device_model": "X690-48x (2-slot stack)",
  "device_os_version": "32.6.1.2",
  "device_cli_syntax": "EXOS",
  "device_role": "core",
  "log_source": "syslog",
  "enrichment_status": "success"
}
```

#### **Debug Output: Stdout**

**Purpose:** Real-time debugging and verification

**Format:** Pretty-printed JSON with emoji markers
```
✓ Enriched log: device=10.139.38.188, vendor=Extreme Networks, event=INTERFACE_DOWN
```

**Enabled:** During testing/troubleshooting  
**Disabled:** In production (performance)

## Dependencies

### Upstream
- **Network Devices:** Send syslog to port 5000 (UDP/TCP)
- **Device Enrichment Service:** HTTP API for metadata lookup

### Downstream
- **Kafka:** Publishes enriched logs to `network-logs` topic
- **Anomaly Detector:** Consumes from `network-logs`

---

## Data Flow

```
Network Device → Syslog (UDP 5000) → Logstash
                                         ↓
                                    Grok Parse
                                         ↓
                                  Event Type Detection
                                         ↓
                                  Interface Extraction
                                         ↓
                              Device Enrichment (HTTP)
                                         ↓
                              Kafka (network-logs topic)
                                         ↓
                                  Anomaly Detector
```

## Performance Characteristics

### Throughput
- **Tested:** 10,000 messages/second
- **Capacity:** 50,000 messages/second (with tuning)
- **Bottleneck:** HTTP enrichment calls (mitigated by Redis caching in enrichment service)

### Latency
- **Parsing:** <5ms per message
- **Enrichment:** 58ms (cached) / 83ms (cold)
- **Total:** 60-90ms end-to-end

### Resource Usage
- **Memory:** 1.5GB average, 2GB peak
- **CPU:** 40-60% on 2 cores at 5K msg/sec
- **Network:** 5-10 Mbps at typical load

```bash
curl http://localhost:9600/_node/stats
```

- `events.in`: Total messages received
- `events.out`: Total messages published to Kafka

```bash
docker logs smart-noc-logstash --tail 100
```

**Normal Output:**
```
[INFO] Successfully started Logstash API endpoint
[INFO] Pipeline started
```

**Error Indicators:**
- `[ERROR] Connection refused` → Kafka unavailable
- `[WARN] Enrichment timeout` → Device enrichment service slow/down
- `[ERROR] Grok parse failure` → Unexpected syslog format

## Troubleshooting

### Issue: Messages Not Reaching Kafka

**Symptoms:**
- Logstash logs show input but no output
- `events.out` count not increasing

**Diagnosis:**
```bash
# Check Kafka connectivity
docker exec smart-noc-logstash curl -I kafka:9092

# Verify Kafka topic exists
docker exec smart-noc-kafka kafka-topics.sh --list --bootstrap-server localhost:9092
```

**Resolution:**
1. Verify Kafka service is healthy
2. Ensure `network-logs` topic exists
3. Check firewall rules (port 9092)

---

### Issue: Grok Parse Failures

**Symptoms:**
- `_grokparsefailure` tag in logs
- Messages not enriched

**Diagnosis:**
```bash
# Check raw syslog format
docker logs smart-noc-logstash | grep "grokparsefailure"
```

**Resolution:**
1. Identify syslog format from device
2. Add custom grok pattern to match
3. Test pattern with sample log

---

### Issue: Enrichment Failures

**Symptoms:**
- `enrichment_status: "failed"`
- Device metadata fields are null

**Diagnosis:**
```bash
# Test enrichment service directly
curl http://localhost:8081/device/10.139.38.188
```

**Resolution:**
1. Verify device-enrichment service is healthy
2. Check if device exists in PostgreSQL `devices` table
3. Verify Redis cache connectivity

## Scaling Considerations

### Horizontal Scaling
- Deploy multiple Logstash instances behind load balancer
- Use consistent hashing for device-based partitioning

### Vertical Scaling
- Increase Java heap: `-Xmx4096m`
- Add more workers: `pipeline.workers: 4`

### Optimization
- Disable stdout output in production
- Tune Kafka batch settings for throughput
- Enable persistent queue for reliability

---

## Security

### Network
- Firewall port 5000 to only allow trusted device subnets
- Use TLS for syslog input (port 6514)

### Data
- Sensitive data filtering (passwords, SNMP community strings)
- PII redaction in logs

### Access Control
- Logstash monitoring API requires authentication
- Kafka topic ACLs restrict write access
