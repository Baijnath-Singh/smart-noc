# Redis Cache

**Service Name:** `smart-noc-redis`  
**Image:** `redis:7-alpine`  
**Technology:** Redis 7.x  
**Status:** Infrastructure (Caching Layer)  
**Uptime Target:** 99.5%

---

## Overview

Redis provides **high-speed in-memory caching** for the Device Enrichment Service, reducing database queries and achieving sub-second response times for device metadata lookups.

---

## Service Configuration

### Ports
- **6379 (internal):** Redis server
- **6380 (host):** Mapped external port

### Resources
- **Memory:** 512MB-1GB
- **CPU:** 0.5 cores
- **Storage:** None (in-memory only)

### Configuration
```
maxmemory: 512mb
maxmemory-policy: allkeys-lru  # Evict least recently used keys
appendonly: yes  # Persistence enabled
save: 900 1  # Save if 1 key changed in 15 minutes
```

---

## Data Structures

### 1. **Device Cache**

**Key Pattern:** `device:{device_id}`  
**Type:** String (JSON serialized)  
**TTL:** 3600 seconds (1 hour)

**Example:**
```
Key:   device:10.139.38.188
Value: {"device_id":"10.139.38.188","vendor":"Extreme Networks","device_family":"EXOS",...}
TTL:   3600
```

**Set Command:**
```redis
SETEX device:10.139.38.188 3600 '{"device_id":"10.139.38.188",...}'
```

**Get Command:**
```redis
GET device:10.139.38.188
```

**Storage Size:** ~500 bytes per device × 1000 devices = ~500KB

---

### 2. **Cache Statistics**

**Key Pattern:** `cache:stats:{metric}`  
**Type:** Counter/Hash

**Examples:**
```
cache:stats:hits → 103
cache:stats:misses → 17
cache:stats:total → 120
```

**Increment:**
```redis
INCR cache:stats:hits
```

## Cache Performance

### Measured Metrics (Production)

**Hit Rate:** 86% (103 hits / 120 total requests)  
**Hit Latency:** 2ms (Redis lookup)  
**Miss Latency:** 83ms (PostgreSQL query + cache)

**Performance Gain:**
- **Redis vs Cold:** 58ms / 83ms = 30% faster
- **Requests Saved:** 86% of queries don't hit database

**Cost Savings:**
- **Database Load:** Reduced by 86%
- **Connection Pool:** Can be smaller (fewer concurrent queries)

## Cache Invalidation

### Manual Invalidation
```bash
# Clear specific device
docker exec smart-noc-redis redis-cli DEL device:10.139.38.188

# Clear all devices
docker exec smart-noc-redis redis-cli KEYS "device:*" | xargs docker exec smart-noc-redis redis-cli DEL

# Flush entire cache (use with caution)
docker exec smart-noc-redis redis-cli FLUSHALL
```

### Automatic Invalidation
- **TTL Expiration:** After 3600 seconds (1 hour)
- **LRU Eviction:** When memory limit reached
- **Application-Triggered:** Via Device Enrichment Service `/cache/clear` API

**When to Invalidate:**
- Device configuration changes in PostgreSQL
- Vendor/model updates
- IP address changes

## Persistence

### RDB (Snapshotting)
**Enabled:** Yes  
**Schedule:** Every 15 minutes if ≥1 key changed

**Files:** `/data/dump.rdb`

**Manual Snapshot:**
```bash
docker exec smart-noc-redis redis-cli BGSAVE
```

### AOF (Append-Only File)
**Enabled:** Yes  
**Sync Policy:** `everysec` (fsync every second)

**Files:** `/data/appendonly.aof`

**Purpose:**
- Recover cache after restart
- Prevent cold start (all cache misses)

## Troubleshooting

### Issue: Memory Limit Reached

**Symptoms:**
```
(error) OOM command not allowed when used memory > 'maxmemory'
```

**Diagnosis:**
```bash
docker exec smart-noc-redis redis-cli INFO memory | grep used_memory_human
```

**Resolution:**
1. Increase `maxmemory` config
2. Reduce TTL (3600 → 1800 seconds)
3. Enable more aggressive eviction

---

### Issue: Cache Not Persisting

**Symptoms:**
- Cache empty after Redis restart
- All requests hitting database

**Diagnosis:**
```bash
docker exec smart-noc-redis ls -lh /data/
# Check if dump.rdb exists
```

**Resolution:**
1. Verify volume mount in docker-compose.yml
2. Enable RDB snapshots: `save 900 1`
3. Check disk space on host

## Performance Tuning

### Eviction Policy
```
maxmemory-policy: allkeys-lru  # Current (recommended)
```

**Alternatives:**
- `allkeys-lfu`: Least Frequently Used (better for stable workloads)
- `volatile-ttl`: Evict keys with shortest TTL first
- `noeviction`: Return errors when memory full (not recommended)

### TCP Backlog
```
tcp-backlog: 511  # Connection queue size
```

### Timeout
```
timeout: 0  # No client timeout (0 = disabled)
```
